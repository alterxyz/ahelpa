- 组合：ahelpa 独立的 `ahelpa` profile，以 base bundle 为基础并使用终端应用；本次没有添加永久 persona overlay。
- 官方界面在 `DeepSeek-V4.1-Flash` 旁显示固定的 `1017` 角标；角标不能固定或证明服务端模型构建版本。[官方标签实现](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-deepseek-model-label-1017/README.md)

## 已观察到的交流习惯

最初五轮聊天表达流畅，也愿意反驳。被质疑“一开始说清全部需求”后，DSH 修正了部分观点，同时保留探索与交付的区分。默认回答偏长、偏结构化；明确要求像聊天那样只接两三句后，能够收短。

它也使用过无依据的“90%”，被追问后承认是修辞。措辞漂亮的主张仍需证据；这几个样本不能证明诚实率，也不能定义固定人格。

在入职讨论中，它提出一个异议：历史任务分工可能自我强化，应该在隔离条件下逐步尝试真实任务。这是值得验证的建议，不是它已经擅长这些任务的证明。

## 复做 fixture 的语义

在一次性隔离目录重建这些小题。本记录保留整理后的结果与语义，不附带 benchmark runner，也不提交原始运行日志。

### 时长解析器

- 函数为 `parseWindowSeconds(input: string): number`；非法输入必须抛出 `Error`。
- 去掉首尾空白，至少包含一个 ASCII 非负整数紧接小写 `h`、`m` 或 `s` 的 token；允许前导零。
- token 可以相邻，也可以用空白隔开；单位至多出现一次，严格按 h/m/s 顺序，可省略某个单位。数字与自己的单位之间有空白则非法。
- 分、秒可大于 59。拒绝正负号、小数、指数、其他字符、错误运行时类型、总值为零、不安全计算，以及超出含端点上限的总值。
- 初始上限为 86,400 秒；原生恢复后仅将上限改为 3,600，语法和错误规则不变。旧期望应按新规范作合法调整。
- 主 Agent 矩阵为 10 个初始合法示例、26 个非法或类型示例、96 个组合：h 取 `[0,1,2,6,12,23]`，m、s 各取 `[0,1,59,90]`。上限变化后重新判断预期结果。全零抛错，超出当前上限抛错。
- 只允许改解析器和有意义的测试，README 不变；不向辅助 Agent 暴露主 Agent 的 oracle，最后一次编辑后再验收。

### 权限审阅

预期规则：先要求 principal 已登录、active，且与文档处于同一 workspace，再要求至少一项授权成立：public、owner 或 `sharedWith` 中显式包含该用户。“Public”不能跳过登录、active 或租户隔离。

预埋三个故障组：把 public 捷径放在前置检查之前、owner 判断早于 tenant 检查、把分享数组当 boolean 而不查成员。在全新会话里另审一份正确实现，不要求凑故障数量。保留源码原文，独立重跑报告用例，恢复 mutation 后检查源码 hash。

### 交流与证据

不给截图，也不给支持“提速 30%”的测量。要求回复 120–180 字、至多一个问题、两个可能方向和低成本下一步。独立统计 Unicode 字符并读实际内容；单看长度不能证明回复处理了缺失证据。
